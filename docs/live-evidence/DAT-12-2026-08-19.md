# DAT-12 live evidence — 2026-08-19

**Object measured:** whether the 20-level endpoint's reproduced second-message failure follows
the WebSocket or persists across a fresh socket under the same account credentials. Read-only
market data only; no order API was called.

**Completed:** 10:18:04 IST, 2026-08-19. Each socket condition had a 15-second collection window.
The same-day Dhan master and external credential handle were the same inputs as DAT-11.

Two disjoint 50-instrument sets were used. Message one was headed by the August NIFTY and
BANKNIFTY futures; message two was headed by the September NIFTY and BANKNIFTY futures. The
remaining instruments were disjoint NIFTY 2026-09-01 options.

| Condition | Instruments receiving / requested | Packets | Per-instrument min–max | Result |
|---|---:|---:|---:|---|
| Message 1 on socket A | 50 / 50 | 5,880 | 14–126 | worked |
| Message 2 on socket A | 0 / 50 | 0 | 0–0 | silently failed |
| Same message-2 set alone on fresh socket B | 50 / 50 | 3,862 | 8–118 | worked |

**Conclusion:** **socket-scoped** for the reproduced 50+50 condition. The unchanged second set
failed on the already-loaded socket and succeeded in full on a fresh socket, ruling out an
account-wide block for this experiment.

**Scale qualification:** an earlier 2+2 run completed at 10:16:19 IST and delivered both
same-socket messages (roughly 166–172 packets per instrument), as well as the fresh-socket set.
Therefore the earlier ledger wording “only the first subscription message a socket ever receives
is honoured” is contradicted at small load. The supported statement is narrower: the 50+50
failure is socket-local and reset by reconnect; the exact cumulative-load/message-count response
surface between 2+2 and 50+50 remains unmeasured.
